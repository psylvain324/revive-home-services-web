# Revive Co service platform

A production React/Netlify platform for Revive Co: public marketing site, live availability, appointment booking and inquiries, Stripe Checkout, customer records, expense tracking, tax-reserve planning, analytics, and a secure administrator portal.

## What is included

- Responsive residential and commercial cleaning website
- Three-step booking flow with business-hours, blocked-time, service-duration, buffer, and double-booking controls
- Quote-only, pay-later, deposit, and full-payment paths
- Stripe-hosted Checkout for cards and eligible Apple Pay / Google Pay wallets
- Verified Stripe webhook and payment-confirmation page
- Password-protected admin portal at `/admin`
- Sales, booking, customer, service-mix, conversion, and traffic-source dashboards
- Availability, price, service, add-on, payment, and tax-reserve controls
- Manual expense ledger and estimated tax reserve (planning only)
- First-party Sales Vision attribution and event tracking, with no form text, address, or payment credentials placed in analytics events
- Privacy, terms, accessibility, security headers, sitemap, robots file, and custom social card

## Run the public UI locally

Requires Node.js 22 or newer.

```bash
npm install
npm run dev
```

Vite serves the UI at `http://localhost:5173`. In development only, the booking page displays a safe demo schedule when the local API/database is unavailable. It does not simulate or accept payment.

## Run the complete platform locally

Install or invoke Netlify CLI, initialize Netlify Database for the linked site, copy `.env.example` to `.env`, and provide the environment variables below. Then run:

```bash
npx netlify dev
```

The complete site and functions are served at `http://localhost:8888`.

## Required Netlify environment variables

| Variable | Purpose |
| --- | --- |
| `NETLIFY_DB_URL` | Supplied by Netlify Database after initialization |
| `ADMIN_EMAIL` | Case-insensitive administrator email |
| `ADMIN_PASSWORD_HASH` | Scrypt hash generated by `npm run admin:hash -- "strong password"` |
| `SESSION_SECRET` | Random secret containing at least 32 characters |
| `STRIPE_SECRET_KEY` | Stripe secret key; start with a test-mode key |
| `STRIPE_WEBHOOK_SECRET` | Signing secret for the production webhook |

Never commit real values. `.env` and Netlify local state are ignored by Git.

## Stripe activation checklist

1. Add Stripe test keys to Netlify environment variables.
2. In Stripe, configure the business profile and payment methods. Hosted Checkout displays eligible wallets based on the customer's browser and device.
3. Create a webhook endpoint at `https://YOUR_DOMAIN/api/stripe-webhook` for `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, and `checkout.session.expired`.
4. Put the webhook signing secret in `STRIPE_WEBHOOK_SECRET`.
5. In `/admin`, enter reviewed service/add-on prices, choose a deposit percentage, and then enable online payment.
6. Enable Stripe Tax in `/admin` only after the business address and applicable tax registrations are configured in Stripe.
7. Complete test-mode bookings, verify the dashboard, then replace test credentials with live credentials.

Payment activation is intentionally fail-closed: a service with no price remains quote-only, and public payment controls stay disabled without a Stripe secret key.

## Database

The schema and safe seed data are in `netlify/migrations/0001_revive_platform/migration.sql`. The initial migration creates settings, business hours, blocked time, services, add-ons, customers, bookings, collision-proof booking slots, inquiries, expenses, and analytics events. Seeded services do not have prices, preventing an accidental charge before the owner enters approved amounts.

## Netlify deployment

The repository is configured with `npm run build`, `dist`, `netlify/functions`, Node.js 22, SPA fallbacks, and durable relational storage through Netlify Database.

Before the first deploy, authenticate and link this checkout to the intended Netlify project:

```bash
npx netlify login
npx netlify link
```

Initialize Netlify Database, configure the required secrets above, and validate the exact production build locally:

```bash
npm ci
npm run audit:site
npx netlify build --offline
```

Push the linked production branch for continuous deployment, or create a draft deploy with `npx netlify deploy --build`. The canonical production URL in metadata is `https://www.revivecoservices.com/`; attach that domain to the Netlify project before launching.

## Operational notes

- Expense and tax-reserve figures are bookkeeping aids, not tax filing software or professional advice.
- Customers should never put alarm or lock codes in website forms.
- Admin sessions are signed, HTTP-only, same-site cookies and expire after eight hours.
- Cancelled, no-show, failed, and expired payment bookings release their held schedule slots.
- The footer credit and `data-salesvision-site` marker identify the Sales Vision Consulting implementation.
